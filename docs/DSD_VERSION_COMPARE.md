# DSD 버전 비교

**공시 검토 → DSD 버전 비교**에서 수정 전·후 두 문서를 선택합니다. XML 표를 포함한 DSD/ZIP과 단일 XML 사본을 읽으며 표가 없는 XML 본문도 비교할 수 있습니다. 독자적 바이너리 DSD 형식이나 DART 편집기의 전체 서식을 구현한 기능은 아닙니다.

## 확인하는 변경

- 표의 숫자·문구·머리글, 셀 병합·머리글 구분, 표·행·열의 위치 변경을 구분합니다. 원문 텍스트와 변경 전·후 멤버·표·행·열 위치를 보관합니다.
- 숫자는 `Decimal`로 비교하며 **변경 후 값 − 변경 전 값**을 계산합니다. `(1,000)`과 `-1000`처럼 값이 같고 표현만 다르면 숫자 표시 변경입니다. 부호가 반대인 값에는 부호 확인 근거를 함께 남깁니다.
- 공란·대시·0은 서로 다릅니다. 표시 단위 안내가 바뀌면 별도로 표시하고 원·천원·백만원을 자동 환산하지 않습니다. 백분율의 같은 수치와 표시 변경도 구분합니다.
- XML 표 밖의 문단·제목·인라인 문구와 직접 본문·뒤따르는 텍스트를 읽습니다. 이미지, 글꼴·색·쪽 나눔, XML 속성 전체와 바이트 단위 공백 변경은 비교 대상이 아닙니다.

## 대응과 확인 필요 상태

파일명·ZIP 안 XML 파일명이 달라지거나 앞에 표가 추가됐다고 이후 표를 모두 다른 금액으로 처리하지 않습니다. 먼저 같은 셀 격자, 다음으로 유일한 제목·주석 경로, 다음으로 유일한 문구 목록을 사용해 표를 찾습니다. 표 안에서는 같은 행 원문과 유일한 행 이름, 전체 열 머리글을 사용합니다. 고정된 격자를 유지한 행·열의 이름 수정은 같은 물리 위치를 기준으로 비교하며 `matchBasis`에 기록합니다. 동일한 표·행의 물리 격자가 그대로인 경우는 문서 일치 여부를 확인하는 빠른 경로를 사용합니다.

변경된 표·행·열에 같은 이름이나 같은 내용이 여러 개 있으면 첫 후보를 임의 선택하지 않습니다. **대응 확인 필요** 상태와 모든 미대응 셀을 남깁니다. 양쪽에 대응되지 않은 표가 있으면 크게 수정된 같은 표일 수 있으므로 추가·삭제 여부를 직접 확인해야 합니다. 한쪽에만 남은 표도 추가·삭제 **후보**로 표시합니다. 이 결과는 회계·공시 항목의 동일성에 대한 승인이 아닙니다.

같은 문구가 반복되는 본문과 큰 문서의 문단 대응도 확인 필요 상태로 남길 수 있습니다. 본문 대응 후보의 잠재적 비교 횟수가 2,000,000을 넘으면 유일한 정확 일치 문구만 연결하는 제한된 방법으로 전환합니다. 이 경우 미대응 문구와 상대 순서 변경을 숨기지 않습니다.

표·행 이동은 숫자 변경과 구분합니다. 앞선 표·행이 추가되면서 원문 위치가 이동한 경우도 구조 변경과 `movedCells`에 포함됩니다. 자동 합계 검증이나 수정, 합산, 전기 금액의 당기 이월은 수행하지 않습니다.

## 원본과 보안

비교 전·후에 두 원본의 SHA-256을 다시 확인합니다. 도중에 원본이 바뀌거나 읽기·예산 검사가 실패하면 부분 비교 행을 비우고 오류로 반환합니다. 원본은 덮어쓰지 않습니다. 공개 결과에는 로컬 절대경로를 기록하지 않고 파일명과 ZIP 안 원본 위치만 포함합니다. SHA는 원본 대응용이며 파일의 진위나 작성자 신원을 인증하지 않습니다.

DTD·외부 엔티티·네트워크 XML 해석, ZIP 경로 이탈·중복·실행파일·암호화 등은 기존 DSD 판독기의 검사를 재사용합니다. UNC·URL 입력은 파일을 열기 전에 거부합니다. 매핑된 네트워크 드라이브나 운영체제의 모든 경로 재지정까지 격리하는 보안 샌드박스는 아닙니다.

파일당 DSD 100MB, 단일 XML 32MB, XML 64개, 표 2,000개·셀 100,000개 등의 기존 한도에 더해 본문 10,000문단·전체 16Mi 문자·문단 1Mi 문자를 적용합니다. 결과는 250,000행·본문 표시 64Mi 문자 이내이며 한도 초과를 조용히 잘라 일치로 표시하지 않습니다. 표시용 절 경로는 최근 16개 제목·각 2,000자 이내이며 제목 원문은 별도 본문 텍스트로 보존합니다.

## API

```python
from xbrl_filing.dsd_diff import compare_dsd_versions

report = compare_dsd_versions('수정전.dsd', '수정후.dsd')
assert report['schema'] == 'account-normalizer-dsd-diff/1'
```

`status`는 `pass`(지원 범위에서 변경 없음), `differences`(변경 있음), `needs-review`(대응 확인 필요), `error`입니다. `before/after`는 파일명·SHA·표/셀/문단 수, `sourceHashes`는 두 원본 SHA, `rows`는 변경 전후 텍스트·숫자·원본 위치·근거, `tablePairs`는 표 대응 근거와 일치·이동 셀 수를 제공합니다. `counts`는 변경 종류별 건수와 `changes`, `matchedTables`, `matchedCells`, `unchangedCells`, `movedCells`, `ambiguous`입니다. `rows`에는 변경만 저장하며 변경이 없는 모든 셀을 중복 출력하지 않습니다.

공용 `xbrl_filing.dsd_document.extract_dsd_narratives(path)`는 표 밖의 전체 텍스트와 원본 해시·표시용 절 경로를 반환합니다. 표 전체를 메모리에 적재하는 `read_document`와 달리 이 API는 표 셀 목록을 만들지 않습니다. 엑셀 본문 추출에서도 같은 안전 판독기를 사용합니다.

비교의 `pass`는 이 도구가 읽는 문구·값·표 구조의 일치입니다. DSD 파일의 완전한 바이너리 동등성, 주석 완전성, 회계 적정성, XBRL 태깅·공식 작성기 검사·DART 접수 성공을 의미하지 않습니다.
