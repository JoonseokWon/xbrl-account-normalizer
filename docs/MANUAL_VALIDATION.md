# v0.12.0-preview.1 사용자 확인 목록

버전별 자동 검사 수·통과/제외·소스/EXE 확인 범위는 릴리스의 `validation-summary.json`을 참고하세요. 자동 검사는 아래 수동 목록 전체나 실사용 자료의 공시 적정성을 확인했다는 뜻이 아닙니다. 공시 준비는 [IFRS_DART.md](IFRS_DART.md), 기존 GL XML은 [XBRL_GL.md](XBRL_GL.md), 감사 입력 예제는 DEMO_RESULT.md에 범위를 구분했습니다.

## 공시 검토

1. 상단 `공시 검토 → DSD·IXD 숫자 대사`에서 직접 준비한 로컬 문서 두 개를 선택합니다. XML 표가 없는 이진 DSD와 편집용 IXD는 오류를 안내해야 합니다.
2. DSD 셀과 IXD 팩트의 회사·기간·단위·차원을 확인한 뒤 대응을 연결합니다. 천 단위 1,234는 배율 1,000일 때 1,234,000과 비교하고, `(20)`은 -20이어야 합니다. 공란·대시는 자동 0이 아니어야 합니다.
3. 당기와 전기, 다른 통화·회사·차원, 중복 팩트, 값 차이, 미대응을 각각 확인합니다. 일부 대응이 일치해도 미대응·전체 공시 검증이 끝났다는 안내가 없어야 합니다.
4. 대응표와 JSON/CSV 결과를 저장합니다. 원본을 수정한 사본으로 바꾸면 저장한 대응표의 원본 지문 불일치를 안내하고 재확인을 요구해야 합니다. 입력 DSD·IXD 자체는 바뀌지 않아야 합니다.
5. `주석·변경 이력·다음 연도 업무`에서 새 업무를 만들고 회사·기간을 직접 입력하거나 기존 공시 JSON을 가져옵니다. 원장 업무와 별개로 주석과 팩트를 편집·저장·다시 열 수 있어야 합니다.
6. 주석 서술과 공시 팩트를 수정한 뒤 변경 이력에서 이전/이후 값을 확인합니다. 과거 상태로 복원해도 기존 이력은 지워지지 않고 새 복원 기록이 남아야 합니다.
7. 같은 업무를 두 창에서 수정한 뒤 저장하면 나중 저장 시 외부 변경 충돌을 안내해야 합니다. 이력과 현재 상태가 불일치하는 파일을 열면 오류를 안내해야 합니다. 해시는 서명이나 작성자 신원 인증이 아닙니다.
8. 다음 연도 업무에서 이전 당기의 수치가 비교기간에 그대로 남고 새 당기 수치는 공란이어야 합니다. 모든 승인을 다시 요구하고 윤일 조정이 있으면 기록해야 합니다.
9. 공시 입력 JSON 초안을 저장한 뒤 기존 `IFRS/DART 공시 XML` 화면에서 열고 공식 택사노미와 개별 항목을 검토·승인합니다. 자유 서술 주석을 자동으로 공식 XBRL 팩트에 넣은 것으로 표시하지 않아야 합니다.

## v0.9 IFRS 공시 XML

1. 업무 메뉴 또는 변환 결과에서 `IFRS/DART 공시 XML`을 엽니다. 기존 원장 업무가 없어도 공시 엑셀을 선택할 수 있고, 공시 작업이 기존 GL Session을 바꾸지 않는지 확인합니다.
2. 이용 권한이 있는 공식 로컬 `.xsd` 진입점과 전체 의존 택사노미 폴더를 준비합니다. 전용 택사노미 폴더 밖에 결과를 저장합니다. IFRS 2025는 2026 보고기간에도 현행이라는 공식 안내와 회사의 IAS 1/IFRS 18 조기 적용 기준을 확인하고 진입점을 선택합니다.
3. `공시 엑셀 양식 만들기`로 빈 파일을 만듭니다. 공시정보와 공시항목을 채워 가져오고 작성예시 시트는 변환되지 않는지 확인합니다. 회사별 별도 XLSX·CSV·JSON을 사용할 수 있어야 합니다.
4. 회사 식별자·체계 URI·당기기간·연결/별도·비교기간을 확인합니다. 식별자·항목ID·원본코드의 앞자리 0을 텍스트로 유지하고 XML 내부 ID와 원본 항목ID를 구분합니다.
5. BS·PL·CF·CE·NOTE의 확정 팩트를 읽고 항목별 공식 QName·시점/기간·단위·decimals·명시적 차원을 확인합니다. 원장 순증감으로 BS 잔액·CF를 생성하지 않아야 합니다. 열린 업무에서 가져오는 값은 기존 BS 표시값뿐이어야 합니다.
6. `값=1,234`, `표시배율=1000`의 정규값이 `1234000`인지, decimals=-3을 지정해도 다시 1,000배 하지 않는지 확인합니다. 쉼표·괄호 음수와 문자·날짜·참거짓의 빈 단위를 확인합니다.
7. 확인자를 입력하고 항목을 승인합니다. 미확정 항목은 XML 저장을 차단하고, 회사 범위·값·개념·기간·단위·차원·택사노미 변경 시 승인을 취소하는지 확인합니다. 같은 concept/context/unit 중복을 소계와 상세라는 이유로 자동 합산하지 않아야 합니다.
8. 공시 업무를 `.acfiling`으로 저장·복원합니다. 원본과 택사노미는 별도 보관해야 합니다. 같은 택사노미 지문이면 저장된 승인을 확인하고, 다른 지문이거나 참조가 없으면 재승인이 필요한지 확인합니다. 업무 JSON은 서명 없는 설정이며 확인자 이름도 인증된 서명이 아님을 구분합니다.
9. v0.9 실행팩에 포함한 Arelle 2.47.3이 실제 로컬 DTS를 읽고 XBRL 2.1·자료형·기간·차원을 검사하는지 확인합니다. 계산 1.0/1.1 관계에 필요한 팩트가 없는 경우 미수행 범위가 기록돼야 합니다. Formula·필수 공시/주석 완전성·DART 접수는 수행한 것으로 표시하지 않아야 합니다.
10. 검사 통과 뒤 `financial-report.xbrl`, 근거 JSON, `공시검사결과.html`, `DART_입력대사.csv`와 파일 해시가 새 완료 폴더에 있는지 확인합니다. 실제 원본·택사노미를 바꾼 복사본에서는 저장이 중단되고 이전 완료 결과가 유지돼야 합니다.

## v0.9 DART 엑셀 참조와 공식 작성기

1. `DART 공식 엑셀 참조 선택`으로 공식 개념·역할 목록을 읽고 해당 재무제표 역할과 한국어·영문 이름으로 항목을 찾습니다. 이 엑셀을 XSD로 바꾸거나 공식 namespace URI를 추정하지 않아야 합니다.
2. 개념·기간·단위·값·확인자 승인을 마치고 대사표를 저장합니다. `DART_입력대사.csv`·`facts.json`·`공시대사결과.html`·검사 JSON이 생성되며 XBRL XML은 없어야 합니다. `concept-metadata-only`, `xmlGenerated=false`와 XSD·실제 차원 관계·계산·접수 미수행 표시를 확인합니다.
3. 설치된 DART 스키마 선택으로 공식 작성기 설치 폴더의 진입점을 읽는지 확인합니다. 작성기 업데이트로 스키마 해시가 바뀌면 개념 연결과 승인을 다시 확인해야 합니다. 기술검사 실행 기록은 공식 작성기 전체 검사·최종 파일 생성과 별도로 확인합니다.
4. [DART 접수시스템](https://filer.fss.or.kr/raaf001/search.do)의 최신 공식 작성기로 제출용 최종 파일을 생성·검사하고 DART 편집기에서 추가 작성·삽입·제출을 확인합니다. 앱 XML/CSV의 자동 불러오기와 최종 수리 여부는 검증된 것으로 간주하지 않습니다.
5. 공개 실행팩·예제·소스에 IFRS/DART 원본 택사노미·공식 참조 엑셀이 재배포되지 않는지 확인합니다. 사용자는 이용 권한이 있는 로컬 파일을 직접 선택합니다.

## XBRL GL XML

1. 계정 연결을 완료한 업무를 열고 변환 결과 상단의 `XBRL GL XML 저장`을 누릅니다. 미확정이 남으면 상단에서는 검토 엑셀을 저장할 수 있습니다.
2. 결과의 XML·`검사결과.html`·검사 JSON·원본 행 연결 JSONL·오프라인 택사노미 패키지를 확인합니다. `검사 보고서 열기`에서 회사·기간·행 수·차대 합계와 오류·주의·미수행 구분을 확인합니다. 원본 계정과 공통 계정이 각각 보존되는지 확인합니다.
3. 다른 도구에서는 함께 저장한 택사노미 패키지를 등록해 XML을 열고, 전표번호·차대변·앞자리 0·은행/계좌 세부정보를 확인합니다.
4. BS는 기말 표시값의 부호·상세/소계/합계를 유지하는 GL balance 자료입니다. IFRS/DART 공시 재무제표로 해석하지 않습니다.

## 저장한 XML 다시 검사·원본 연결

1. 업무 메뉴 또는 변환 결과의 `저장한 XML 다시 검사`에서 이 앱이 만든 결과 폴더를 선택합니다. 원본 원장을 열지 않은 상태에서도 XML·행 연결·스키마 패키지·파일 해시의 내부 일치 여부를 확인할 수 있어야 합니다.
2. `검사 결과`에서 오류의 문서·이유·관련 위치를 확인합니다. 원본 원장을 다시 읽어 대사한 결과나 보고서의 진위를 인증하는 검사와 구분합니다.
3. `출력 행·원본 연결`에서 문서를 선택하고 이전/다음 100행으로 이동합니다. 첫 행·마지막 행의 앞자리 0과 전기일·차대 금액이 저장 결과와 일치하는지 확인합니다. 행을 두 번 눌러 은행·계좌·거래처 등 저장된 연결 정보를 확인합니다.
4. 같은 원본의 업무를 열었을 때만 `열린 업무의 원본 행 보기`가 활성화되는지 확인합니다. 다른 회사·다른 원본·잘못된 출처 메타데이터에서는 원본 이동을 비활성화해야 합니다.
5. 결과 폴더를 복사한 뒤 복사본 XML의 금액이나 계정코드를 바꿔 재검사합니다. 오류가 표시되고 결과를 통과한 것처럼 안내하지 않아야 합니다. 실제 원본과 기존 완료 결과는 변경하지 않습니다.
6. 재검사 HTML은 새 파일명으로 저장합니다. 원본 결과를 덮어쓰지 않으며, 다른 위치에 저장한 HTML에서는 잘못된 상대 파일 링크를 만들지 않아야 합니다.
7. v0.7에서 저장한 결과도 열어 봅니다. 당시 행 연결에 기록하지 않았던 일자·세부정보가 새로 만들어지지 않고 빈 값으로 표시되는지 확인합니다.

재검사는 이 앱이 저장한 GL 결과 폴더를 대상으로 합니다. 검사 기록과 파일을 함께 바꾼 경우의 진위·실제 회계 분류·공시 접수 여부까지 확인하는 기능은 아닙니다. v0.9부터 Arelle는 공시 DTS 검사를 위해 Windows 실행팩에 포함하며, 위 GL 재검사와 공시 준비 검사는 구분합니다.

## 진행률과 XML 저장 취소

1. 큰 원장의 XML 저장·내용 확인 단계에서 현재 단계와 처리 행 수가 표시되는지 확인합니다.
2. 저장 중 `XML 저장 취소`를 누르고 작업 종료를 기다립니다. 현재 업무의 매핑·원본·이전 완료 결과가 유지되고 이번 미완성 출력 폴더가 남지 않아야 합니다.
3. 취소한 뒤 다시 XML을 저장해 정상 완료와 보고서 열기가 가능한지 확인합니다.
4. 완료 폴더로 확정된 뒤 도착한 늦은 취소 요청은 이미 완료한 결과를 취소로 오표시하지 않아야 합니다.

## Windows 화면 흐름

1. 실행팩을 모두 풀고 `AccountDataNormalizer.exe`를 실행합니다. Python이 설치되지 않은 PC에서도 실행되는지 확인합니다.
2. `새 파일 열기`로 확인할 회사의 `.xlsx`를 선택합니다. 회사 정보를 확인한 뒤 `열 연결 설정`에서 원장·재무상태표의 시트와 열을 선택합니다. 테스트에는 `samples/계정매핑_합성입력.xlsx`를 직접 선택할 수도 있습니다. 노바부품 원장은 `분개장`에서 분개를 읽고 `GL_Data`만 변환 시트로 선택합니다.
3. 계정 후보를 불러와 회사·원본 코드·계정명으로 검색하고, 미확정 필터를 켰을 때 목록과 상세 내용이 함께 바뀌는지 확인합니다.
4. 확인자를 입력하고 지급수수료 후보를 연결·제외·미확정으로 변경해 봅니다. 미확정 계정이 자동 승인되지 않는지 확인합니다.
5. 변환 결과에서 원본 행과 금액, 미확정·오류 수를 확인합니다. 검토 엑셀을 저장하고 결과 폴더를 엽니다.
6. 다른 파일을 선택하면 이전 회사코드·확인자·열 연결·검토 목록·결과와 결과 폴더 열기 상태가 초기화되는지 확인합니다. 파일 선택 취소와 읽기 실패 시에는 기존 작업이 유지되는지, 저장하지 않은 변경을 버리기 전에 안내하는지 확인합니다.
7. 창 크기와 Windows 배율을 바꿔 본문을 스크롤하고 상단 버튼·한글 입력을 확인합니다. 맑은 고딕이 선택되는지, 작은 안내 글자가 읽기 편한지, 모니터 사이로 창을 옮겨도 글자가 선명한지 확인합니다.

초기 화면 렌더와 EXE 초기화·리소스 점검은 수행 범위를 별도로 기록합니다. 위 업무 흐름과 회계 값의 확인을 대신하지 않습니다.

## 1. 후보와 자동 확정 구분

1. `samples/계정매핑_합성입력.xlsx`를 복사합니다.
2. 매핑표의 지급수수료 행을 미확정으로 두고 `--no-history`로 변환합니다.
3. `매핑후보`에는 E5204 후보와 근거가 보이고, 표준원장에서는 해당 행이 미확정으로 남는지 확인합니다.
4. 후보와 동일한 숫자로 원본 계정코드를 바꿔도 코드가 같다는 이유로 자동 승인되지 않는지 확인합니다.

## 2. 승인·거절 이력

1. 복사본에서 지급수수료의 코드를 E5204, 상태를 확인으로 바꾸고 확인자를 입력해 변환합니다.
2. 같은 회사·시스템의 새 입력에서 매핑표를 제거한 뒤 변환하여 승인 이력이 적용되는지 확인합니다.
3. 회사코드, `--system`, 원본계정명 중 하나를 바꾸면 승인이 적용되지 않는지 확인합니다.
4. 매핑표에서 같은 계정을 명시적으로 미확정으로 설정하면 이력으로 재승인되지 않는지 확인합니다.
5. E5204를 거절하고 확인자를 입력해 변환한 다음, 새 입력의 추천에서 해당 코드가 제외되는지 확인합니다.
6. 다시 확인으로 바꿨을 때 최신 결정이 적용되는지 확인합니다. 확인자 이름은 검토 기록의 텍스트이며 로그인 인증이 아닙니다.

## 3. 원본 열 연결

1. 원장 헤더 이름을 바꾸고 `config/column_mapping.example.json`의 원본 열 이름도 맞춥니다.
2. `--column-map`을 사용하면 기존 결과와 같은 계정·금액이 나오는지 확인합니다.
3. 없는 열 이름이나 중복 열 연결을 지정하면 오류가 표시되는지 확인합니다.

## 4. 금액과 출처

- 보통예금·당좌예금은 서로 다른 원본 코드가 보존되면서 A1102로 집계되는지 확인합니다.
- `00101` 등의 앞자리 0, 전표번호, 행ID가 저장 후 다시 열어도 유지되는지 확인합니다.
- 원본 원장 합계와 표준원장 전체 합계를 비교합니다. 미확정 행이 있으면 확인 계정 집계만을 전체 합계로 사용하지 않습니다.
- 재무상태표의 천원 금액이 원으로 환산되며 원장 당기순변동과 구분되는지 확인합니다.
- 중복 전표행·음수 차대·공란 금액이 변환이슈에 남고 연결 데이터가 보류되는지 확인합니다.
- 기존 입력 파일이 변경되지 않고 새 출력 폴더가 생성되는지 확인합니다.

## 자동 확인 명령

```text
python -m unittest discover -s tests -v
python tools/verify_roundtrip.py
python tools/verify_xbrl_ui.py --out 새화면확인폴더
python convert.py --check-xbrl "검사할결과폴더" --out "보고서저장폴더"
```

소스 GUI의 버튼·작업·업무 복원과 새 재검사·HTML 저장·원본 이동 흐름을 시험했습니다. OS 파일선택창은 시험 경로로 대체했고, 취소 버튼 전달 시험에서는 XML 작업을 시험 함수로 대체했습니다. 실제 변환 서비스의 취소와 임시 출력 정리는 별도 자동 검사로 확인합니다. 실제 OS 파일선택창·실사용 자료는 이 수동 목록으로 확인합니다. CLI 재검사는 통과 시 종료 코드 0, 검사 오류가 있으면 2를 반환합니다.

## 통합감사 입력 저장

계정 연결 완료 후 통합감사 입력 저장에서 보조파일과 폴더를 선택합니다. 회사 혼합·통제 누락·차변 차이·미확정 매핑은 차단되는지 확인합니다. 새 입력을 별도 더미 업무의 원장·리드로 등록하고 대사·원본 출처를 확인합니다. 실제 통제의 독립 추출 여부는 사람이 별도로 확인합니다.

## v0.5 반복 업무

- 같은 회사·양식의 여러 월 파일을 선택하고 합계·원본 출처를 확인합니다. 다른 회사·동일 내용 파일·중복 전표행은 합쳐 쓰지 않습니다.
- 회사·ERP별 입력 설정을 저장하고 새 파일에 불러옵니다. 다른 회사·ERP 설정은 적용되지 않아야 합니다.
- 분개 화면에서 1:다수·다수:1·복합분개·반대 분개를 확인합니다. 원본 행을 두 번 눌러 실제 값을 확인합니다.
- 보조자료 열을 연결하고 시산표 차이·누락과 통제 불일치를 확인합니다. 통제 누락을 원장 합계로 채우지 않습니다.
- 업무 저장 후 외부 원본을 옮기고 다시 열어 원장·보조자료·검토 상태를 확인합니다. 불러온 뒤 원본을 바꾸면 저장이 중단돼야 합니다.
- 계정 사전을 수정하고 기존 연결이 미확정으로 바뀌는지 확인합니다.
- 10만 행급 검토 엑셀의 행 수·코드·세부정보를 확인합니다. 큰 원장은 통합감사 v2.3 이상에서 전체 행수와 금액을 확인합니다.
