# 공식 DART 작성기 연동

이 앱은 승인한 공시 입력을 보관하고, 공식 작성기를 열고, 작성기에서 만든 결과와 검사 로그를 모읍니다. 별도로 XBRL 불러오기 **후보**와 공식 설치본에 포함된 기술검사 실행 경로를 제공합니다. 후보 XML 생성, XBRL 기술검사, 공식 작성기의 제출용파일 생성, DART 전송은 각각 다른 단계입니다.

2026-10-29 기준 업데이트: 별도 로컬 연동 시험에서 합성자료를 공식 작성기 본체로 처리해 제출용 IXD를 생성했고, 독립적인 패키지·수치 검사와 공식 기술검사 오류·경고 0건을 확인했습니다. 이 시험용 연결은 v0.12 실행팩의 범용 자동 생성 기능으로 포함하지 않았습니다. 아래 앱 사용 순서는 제품에 포함된 준비·기술검사·기존 IXD 수집 경로이며, 새 `공시 검토` 메뉴는 선택한 DSD·IXD를 읽기 전용으로 대사합니다. 실제 DART 접수는 수행하지 않았습니다.

2026-10-28에 확인한 설치본은 작성기 프로그램 9.01, 실행파일 버전 1.64.0.27, 택사노미·서식 8.6입니다. 설치 위치는 `C:\DART`입니다. 설치 파일과 공식 택사노미 원본은 제품에 포함하지 않습니다. 공식 배포·사용 안내는 [DART 접수시스템 자료실](https://filer.fss.or.kr/raaf001/search.do)을 확인합니다.

## 현재 확인된 범위

| 단계 | 상태와 의미 |
|---|---|
| 설치 확인 | 공식 실행파일의 서명·버전·해시를 확인합니다. 확인한 설치본으로만 앱의 실행 연결을 사용합니다. |
| 승인 입력 보관 | 선택한 DTS, 승인한 값·출처·확인자, 회사·기간 설정을 작업 폴더에 기록합니다. |
| 불러오기 후보 | XBRL 인스턴스, 회사 확장 XSD, 검토 JSON을 만듭니다. IXD는 만들지 않습니다. |
| 후보 기술검사 | 공식 설치본의 `validate_only.exe`로 별도 실행하고 로그·오류·완료 근거를 기록합니다. 통과해도 공식 불러오기나 전체 DART 검사가 통과한 것은 아닙니다. |
| 공식 XML 불러오기 | **현재 배포 UI의 사용 가능한 진입 경로를 확인하지 못했습니다.** 설치 DLL에 마법사 코드는 있지만 실제 도구 탭에 메뉴가 없고, 리본 항목을 숨기는 코드도 확인했습니다. |
| 제출용 IXD | 별도 시험에서 공식 작성기 본체의 합성 IXD 생성을 확인했습니다. 제품의 범용 자동 생성 연결은 미포함이며 사용자가 공식 작성기에서 생성한 파일을 수집·대사하는 경로를 제공합니다. |
| 접수·전송 | 이 앱의 기능 범위에 포함되지 않습니다. 공식 작성기에서 생성한 결과를 DART 편집·접수 절차에 따라 처리합니다. |

v0.10 연동 시험 XML은 재무 팩트 30개와 GCD 17개를 포함하는 합성 시험자료로 기술검사 오류·경고 0건을 확인했습니다. 이후 별도 로컬 생성 시험은 보완된 승인 입력 2,164개와 확인된 작성기 메타데이터를 사용했으며, 출력 팩트 2,181개를 별도 검토된 출력 표현 계약과 대사했습니다. 시험 회사 `00000000`과 `연동검증회사`는 실제 제출 회사 정보로 사용할 수 없습니다. 이 실적은 실사용 회사의 전체 주석 완전성이나 DART 접수 수리를 증명하지 않습니다.

## 앱에서 작업을 준비하는 순서

1. 공시 준비 화면에서 실제 회사의 확정 재무제표를 가져오고 공식 DTS에 항목을 연결합니다. 값, 기간, 연결·별도, 차원, 원본 출처를 확인한 다음 승인합니다. DART 엑셀 개념표만 선택한 상태에서는 공식 XBRL 후보를 만들 수 없습니다.
2. `공식 DART 작성기` 화면에서 `설치 찾기` 또는 `EXE 선택`으로 공식 작성기를 선택합니다. 서명·버전·해시 확인 결과를 확인합니다.
3. `승인 입력으로 작업 준비`를 눌러 작업 폴더를 만듭니다. 이후 `기존 작업 열기`로 같은 작업을 이어갈 수 있습니다.
4. 후보가 필요하면 `연동 시험 XML 준비`에서 아래 설정을 직접 확인합니다. 후보·XSD·검토 JSON은 같은 폴더에 유지합니다.
5. `준비한 불러오기 XML 기술검사`를 누르고 `기술검사 보고서 폴더 열기`에서 결과를 확인합니다. 오류 또는 완료 미확인 결과는 해결 전까지 통과로 취급하지 않습니다.
6. `공식 작성기 열기`로 작성기를 엽니다. 현재 확인된 배포 UI에는 외부 XML 불러오기 메뉴가 없으므로 이 지점에서 자동 이관이 이어진다고 가정하지 않습니다. 공식 지원 경로를 확인하거나, 보관한 대사 자료를 사용해 공식 작성기에서 직접 작성합니다.

후보 설정은 회사고유번호 8자리, 국문·영문 법인명, 국문·영문 보고서명, 문서작성일, 양의 정수 기수, 당기 및 전기·전전기 시작일과 종료일, 연결·별도, BS·PL·CE·CF의 공식 서식코드, 확인자를 포함합니다. 영문명과 과거 기간을 자동 번역·추정하지 않습니다. 현재 후보 생성은 사업보고서(`사업보고서` / `Annual Report`)의 연간 기간 구조로 제한합니다. 분기·반기는 전기 동기 등 추가 GCD 기간을 요구하여 지원 미확인으로 차단합니다.

설정 API의 전기·전전기 형식은 다음과 같습니다. 시작일은 종료일보다 늦을 수 없으며, 세 회계기간은 과거부터 순서대로 겹치지 않아야 합니다.

```json
{
  "priorPeriod": {"start": "2024-01-01", "end": "2024-12-31"},
  "secondPriorPeriod": {"start": "2023-01-01", "end": "2023-12-31"}
}
```

기술 확인에 사용한 연결 서식 조합은 BS `D1001`(유동·비유동), PL `D2001`(기능별·세후 포괄손익), CE `D3001`, CF `D4002`(간접법)입니다. 이는 해당 시험자료의 명시 선택입니다. 실제 회사에 그대로 적용할 서식을 자동 결정하는 기준이 아닙니다.

## 현재 배포본의 수동 입력 대안

설치본에는 **`편집 > 붙여넣기`(Ctrl+V)** 명령과 재무제표 금액표의 일반 텍스트 붙여넣기 처리가 있습니다. 엑셀의 직사각형 범위를 복사하면 일반적으로 행은 줄바꿈, 열은 탭인 클립보드 텍스트가 만들어집니다. 공식 작성기는 선택한 셀부터 이 값을 배치합니다. 이 경로는 파일의 개념코드·서식·차원을 자동 매핑하는 엑셀 가져오기가 아닙니다. 통합문서 파일을 여는 공개 엑셀 가져오기 기능은 확인하지 못했으며, `엑셀 내보내기`는 반대 방향의 기능입니다.

직접 입력할 때는 먼저 공식 작성기에서 해당 회사의 재무제표 서식·계정·기간 열을 구성하고, 확정 엑셀에서 동일한 순서의 **금액 셀만** 복사합니다. 작성기의 첫 금액 셀을 선택해 붙여넣고, 입력된 계정·당기/전기 열·값을 원본과 대사합니다. 처음에는 소수 셀로 위치와 부호를 확인합니다. 붙여넣기 코드는 추상행과 숨김열 등을 별도로 처리하고 행의 부호 가중치를 값에 곱하므로, 보이는 행 수가 같다는 이유만으로 결과를 확정하면 안 됩니다. 자본변동표와 주석은 각각 별도 처리 코드가 있어 범위를 별도로 확인합니다.

이는 설치본의 공개 편집 명령과 정적 처리 코드로 확인한 수동 대안입니다. 이 앱이 클립보드 입력을 자동 실행하거나 해당 회사의 전체 보고서를 이 경로로 이관해 검증한 실적은 없습니다.

원본 공식 `.frm`에서 시험자료의 개념 행은 찾을 수 있었지만, 표시 행은 사용 여부·사용자 계정·문서 상태에 따라 달라지고 붙여넣기의 부호 가중치도 실행 중인 문서에서 결정됩니다. 따라서 앱은 원본 서식만 보고 절대 셀 좌표와 붙여넣기 시작 셀을 보장하는 TSV·엑셀을 제공하지 않습니다. 네 번의 붙여넣기로 보고서 전체가 이관된다고 안내하지 않습니다. 특히 시험자료의 30개 팩트 중 1개는 주석이며 네 재무제표 입력 범위 밖입니다.

## 공식 작성기에서 마무리하는 순서

공식 작성기에서 회사·보고서 정보와 재무제표·주석을 작성하고, 작성기에서 제공하는 검사를 진행합니다. 회사의 연결·별도 범위, 비교기간, 필수 항목, 표준·확장 계정과 계산 관계를 확인합니다. 앱의 기술검사 로그는 이 업무 검사를 대신하지 않습니다.

최종 파일은 작성기 상단 **`보고서`의 `제출용파일 생성`** 기능을 실행해 생성합니다. 일반 편집 문서를 `.ixd`로 저장한 것만으로 제출용 생성이 완료되지는 않습니다. `DART파일 테스트저장`도 최종 생성 완료의 근거로 사용하지 않습니다. 메뉴 명칭은 설치본의 공식 안내 문자열과 실제 확인 결과에 근거하며, 외부데이터 가져오기 메뉴의 위치를 이 문서에서 사용 가능한 경로로 안내하지 않습니다.

작성기는 제출용 생성 뒤 **DART파일 저장을 다시 하면 제출용파일 생성을 다시 실행해야 한다고 안내**합니다. 이후 값을 수정하거나 DART파일을 다시 저장했다면 `보고서 > 제출용파일 생성`을 다시 실행하고, 가장 최근 결과와 검사 근거를 수집합니다. 작성기 안내상 재무제표 검사가 완료된 경우에는 다시 저장할 필요가 없습니다. DART 편집기에 삽입할 때도 제출용파일 생성 이후의 결과를 사용합니다.

앱으로 돌아와 `결과 IXD 선택`, 필요시 `CHKINFO 선택`, `원본을 보존하고 결과 수집`을 실행합니다. 파일 구조, 기술검사 로그, 입력 대사, 최종 제출 파일 생성 상태는 각각 확인합니다. IXD 확장자, ZIP 구조, `meta.xml` 또는 빈 `VERIFY` 속성의 존재만으로 전체 검증·최종 생성·접수 완료를 판정하지 않습니다.

## 구현·검증 근거

후보 3의 결과와 검토 기록은 `검증/v0.10.0-preview.1/research/interchange-candidate-2025-native3/`에 있습니다. 후보 2는 전기·전전기 GCD 날짜가 빠졌던 선행 시험자료로 보존하며 불러오기 대상으로 권장하지 않습니다.

- `Fss.Controls-import-period-initialization-il.txt`: 공식 `AnalyzeGCDInfoFromInstance`는 사업보고서도 당기·전기·전전기 날짜를 요구하고, 누락하면 예외를 발생시킵니다. 기간 값은 `PeriodAxis`의 서로 다른 멤버로 구분합니다.
- `fresh-editor-gcd-evidence.json`: 사용자가 공식 작성기에서 새로 저장한 문서를 읽기 전용으로 확인했습니다. 회사 네임스페이스, 파일명, GCD의 `segment` 배치와 기간 멤버의 근거입니다.
- `Fss.Controls-import-business-il.txt`: 영문 GCD는 `en`·`en-us`로 구분하고, 실제 시작일·종료일로 재무 팩트의 당기·전기·전전기를 식별합니다. 다른 기간의 팩트는 이 후보 경로에서 차단합니다.
- `Fss.Windows-import-visibility-il.txt`: 리본 `ribbonButton132`의 `Visible=false`를 무조건 설정합니다. 기존 보고서 메뉴는 별도 `UseOtherXBRL` 설정 조건을 사용하며 확인한 배포 설정에는 해당 키가 없습니다. 앱은 작성기의 설정이나 숨김 상태를 변경하지 않습니다.
- `Fss.Controls-excel-paste-il.txt`, `Fss.Controls-clipboard-format-il.txt`: 일반 클립보드 Text의 행·열 분리, 선택 셀 기준 붙여넣기, 행 가중치 적용의 근거입니다. 실제 회사의 전체 보고서 이관 성공을 뜻하지 않습니다.
- `form-paste-feasibility.json`, `Fss.Controls-paste-weight-il.txt`: 공식 네 서식과 시험자료의 개념 일치 확인 및 절대 셀 좌표·실행 중 부호 가중치를 보장하지 못하는 이유입니다.
- `format-research/installed-menu-strings.json`: 제출용파일 생성 메뉴와 DART파일 저장 후 재생성 안내의 근거입니다.

위 파일은 개발 환경의 `검증/v0.10.0-preview.1/` 아래 별도로 보관한 조사 기록이며 공식 파일을 포함한 원본 조사는 공개 소스·실행팩에 재배포하지 않습니다. 공개 검증 요약은 릴리스의 `validation-summary.json`에서 확인합니다. 정적 코드의 존재는 공개된 UI·CLI·API 사용 경로가 검증됐다는 뜻이 아닙니다. 각 실제 실행의 결과는 해당 작업의 기술검사 보고서와 수집 기록을 확인합니다.
