# DSD 문서 작업

상단 `공시 검토` 메뉴의 `DSD → 엑셀`, `DSD 버전 비교`, `HTML 검토보고서`, `정산표 → DSD`는 같은 작업 창의 네 탭입니다. 파일 읽기·변환·검사는 백그라운드 작업으로 실행합니다. 파일 처리 중 창을 닫거나 다른 작업을 시작하지 않습니다.

## 1. DSD → 엑셀

`DSD 파일 선택`으로 로컬 DSD/XML/ZIP을 고른 뒤 `엑셀로 저장`을 누릅니다. 기존 파일 이름이 있으면 새 이름을 지정합니다. 표는 원본 위치를 보존한 별도 시트로 저장하고 숫자의 표시 단위를 바꾸지 않습니다. 선행 0 코드와 Excel의 숫자 정밀도를 넘는 값은 텍스트로 유지합니다. 비숫자 문구도 수식이 아닌 텍스트로 저장합니다.

표 밖 문구는 `본문` 참고 시트에 원본 위치와 함께 보관합니다. 이 참고 시트의 편집은 DSD에 자동 반영하지 않습니다. 이미지·페이지 구분과 원본 문서 서식은 원본 DSD에서 확인해야 합니다.

수정본을 DSD에 반영하려면 기존 표 시트의 실제 값 셀만 수정하세요. 원본 위치를 기록한 숨긴 시트를 삭제하거나 바꾸지 않습니다. 이 정보는 서명이 아니며 가져올 때 별도로 선택한 원본 DSD와 전체 대응을 다시 검사합니다.

## 2. DSD 버전 비교

수정 전·후 파일을 각각 고르고 `버전 비교 실행`을 누릅니다. 파일명·ZIP 내부 이름이 달라도 표 제목·절·행과 열 문맥 등을 사용해 비교합니다. 같은 제목·내용이 반복돼 어느 항목인지 확정할 수 없는 경우 대응 확인 필요로 남깁니다. 행·열 삽입 뒤 위치 변경과 실제 값 변경을 구분하며 원본 위치는 상세 창에 표시합니다.

필터에서 숫자·문구·추가/삭제·구조/확인 필요로 좁힙니다. 필터는 화면만 바꾸고 저장 결과에서 행을 제외하지 않습니다. 숫자 차이는 `변경 후 − 변경 전`이며 Decimal로 계산합니다. 단위·당기/전기·회계적 합계 관계를 자동 추정하지 않습니다.

비교가 끝난 뒤 원본 파일을 바꿨다면 다시 비교하세요. 비교 JSON과 HTML 저장 시 원본 SHA-256을 재확인합니다.

## 3. HTML 검토보고서

2번 화면에서 비교한 뒤 3번 화면으로 이동합니다. 검토자 이름과 전체 의견을 필요하면 입력하고 `HTML 검토보고서 저장`을 누릅니다. 이름은 텍스트 기록이며 사용자 인증이나 전자서명이 아닙니다. 기존 `DSD·IXD 숫자 대사`의 결과 탭에서도 HTML로 저장할 수 있습니다.

보고서에는 수치·문구·원본 위치·차이·확인 필요 사항이 포함됩니다. 숫자 일치와 제출 적합성을 구분합니다. 앱은 브라우저를 자동 실행하거나 파일을 다른 사람에게 전송하지 않습니다. 결과를 열람 가능한 사람은 해당 회사 정보와 의견을 볼 수 있으므로 사용자가 공유 대상을 정합니다. 외부 스크립트·폰트·이미지를 요청하지 않고 원본 XML을 실행하지 않습니다.

## 4. 정산표 → DSD

원본 DSD 양식과 확정값 `.xlsx`를 선택합니다.

- `1번에서 추출한 엑셀 수정본`: 자료를 읽고 회사·기간·단위와 반영할 값을 확인합니다. 원본 SHA-256·시트·셀 위치·병합·대응 정보가 같은지 다시 검사한 뒤 기존 값 셀만 반영합니다.
- `다른 정산표의 셀을 직접 연결`: 정산표 시트·셀 주소를 입력하고 DSD 대상 셀과 배율을 고른 뒤 `선택한 셀 연결`을 누릅니다. 빈 셀을 명시적으로 연결하면 DSD 기존 값을 비우며 0으로 바꾸지 않습니다. 하나의 DSD 셀에 여러 값을 합산하지 않습니다.

`회사·기간·단위와 반영할 값을 확인했어요`를 체크한 뒤 `새 DSD 초안 저장`을 누릅니다. 파일·모드 변경이나 연결 추가/해제 후에는 다시 확인해야 합니다. 확인 후 원본 파일 바이트가 바뀌면 저장을 차단합니다. 새 파일은 원본과 같은 XML/ZIP 형식을 사용하고 기존 파일을 덮어쓰지 않습니다.

원본 양식의 임의 문단·새 표·목차를 생성하지 않습니다. 복잡한 혼합 서식 셀처럼 내용을 안전하게 바꿀 수 없는 구조는 거부합니다. 변경 XML 외의 ZIP 멤버는 내용 해시를 보존하며 출력 후 표 구조·수치·문구를 다시 읽어 확인합니다.

## 확인 범위

이 작업은 셀 값 반영과 문서 비교입니다. 공식 DSD의 모든 스키마와 바이너리 형식을 구현하거나 DART 접수 가능 여부를 판정하는 기능은 아닙니다. 검증에서는 합성 XML 표·ZIP, 실제 EXE의 오프스크린 화면, 안전하지 않은 파일과 원본 변경 사례를 사용합니다. OS 마우스·키보드·클립보드를 조작하지 않고 공식 작성기·접수 시스템도 실행하지 않습니다.

금감원은 DART 편집기의 문서 작성 후 `파일형식검사`, `전자공시 화면 미리보기`, 전자서명을 포함한 `전송파일 생성`을 별도 단계로 안내합니다. 출력 초안은 이 공식 절차를 통해 별도로 확인해야 합니다.
