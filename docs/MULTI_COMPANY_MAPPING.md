# 여러 회사의 계정 표현 연결

v0.6.0-preview.1은 10개 더미 회사의 계정명 차이를 시험합니다. 실제 회사 자료는 사용하지 않았습니다. 명시된 계정 정의로 만든 정답을 적용한 결과와, 이름만으로 제안한 후보 성능을 구분합니다.

## 결과

| 구분 | 계정 수 | 기존 사전 첫 후보 일치 | 새 사전 첫 후보 일치 | 정의 확인 후 미확정 |
|---|---:|---:|---:|---:|
| 별칭 학습용 6개 회사 | 380 | 50 | 375 | 0 |
| 평가용 4개 회사 | 244 | 25 | 237 | 0 |

전체 원장 1,288행·원본 계정 624개를 변환했습니다. 상세계정 64개와 그룹 3개를 지원합니다. 학습용 더미 계정의 명확한 별칭 322개를 추가하고, 의미가 달라지는 일반명 ‘수수료’는 기존 공통 별칭에서 제거했습니다. 실제 고객사의 계정명만 보고 100% 자동 분류한다는 의미가 아닙니다.

평가용 244개 중 첫 후보와 다른 7개는 회사별 정의로 연결했습니다. 4개는 정산계정·수수료·예치금·선급의 회사별 의미가 달랐고, 3개는 학습용 회사에서 사용하지 않은 Raw materials·Work in progress·Machinery 표현입니다. 이 평가 사례를 공통 사전에 다시 넣어 평가 점수를 올리지 않았습니다. 해당 더미 회사의 확정 연결과 재사용 이력은 결과 폴더에 보관했습니다.

평가 회사는 학습 회사와 다른 조직 표기·회사·ERP·원본 코드를 사용합니다. 다만 같은 정의 목록에서 만든 표현 변형 시험이며, 독립적으로 수집한 실무 데이터의 정확도 평가는 아닙니다. 모델 가중치를 재훈련하지 않았고, 설명 가능한 별칭 누적과 기존 회사별 승인 이력을 사용합니다.

## 앱에서 열기

1. `새 파일 열기`에서 `samples/여러회사매핑/*_원장.xlsx` 중 하나를 선택합니다.
2. `cases.json` 또는 변환 결과의 `input-profile.json`에서 해당 회사코드·원천시스템을 확인합니다.
3. 저장한 사용자 사전이 있다면 업무 → 표준 계정 사전 관리 → 기본 사전 불러오기로 새 사전을 선택할 수 있습니다. 기존 사용자 사전은 자동으로 덮어쓰지 않습니다. 사전 변경 시 현재 연결을 재확인합니다.
4. 계정 검토에서 후보와 정의를 확인합니다. 새 원본 파일은 모든 계정이 미확정으로 시작합니다.
5. 이미 연결한 예제를 보려면 결과 ZIP의 회사별 `.acwork`를 업무 → 업무 열기에서 엽니다. 이 파일의 확인자는 실제 사용자 서명이 아닌 ‘더미 정의 기반 시험 연결’입니다.

회사별 결과에는 표준 JSON·검토 엑셀·통합감사 입력·출처·완료 업무 파일·더미 전용 매핑 이력이 있습니다. 더미 이력은 실제 사용자의 기본 이력에 병합하지 않습니다. 다른 회사의 이름·코드가 같아도 승인 상태를 재사용하지 않습니다.

## 재현

`tools/prepare_company_cases.py`는 v0.5.1 사전과 명시 정의로 새 별칭 사전을 만듭니다. 학습용으로 분리한 사례만 허용하며, 표준 코드 충돌과 의미가 다른 공통명은 제외합니다. 평가 사례와 정답은 `samples/여러회사매핑/cases.json`에 별도로 고정되어 있습니다.

`tools/create_company_workbooks.mjs`는 번들 `@oai/artifact-tool`로 입력 엑셀을 만듭니다. Python 변환 런타임에는 필요하지 않습니다. `python tools/verify_company_mapping.py --out outputs/새검증폴더`로 원장 변환·업무 재열기·이력 범위·원본 행/차대 합계 보존과 7시트 통합감사 입력 저장을 재현합니다. 기존 결과 폴더는 덮어쓰지 않습니다.

공식 DART/IFRS 택사노미 매핑과 XBRL XML 파일 생성·공식 검증은 아직 구현 범위 밖입니다.
