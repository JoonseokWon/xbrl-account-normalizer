# 주석 편집·변경 이력·다음 연도 재사용

공시 검토 업무는 회사와 보고 기간, 기존 공시 입력 팩트, 주석 제목·서술·연결 항목을 `.acdisclosure` 파일 하나에 보관합니다. 인벡터의 코드·비공개 서비스·산출물을 분석하지 않고 독립적으로 구현했습니다.

## 주석과 공시 팩트

- 주석에는 제목, 서술, 연결할 공시 항목 ID 목록을 입력합니다. 연결 목록은 현재 업무의 실제 팩트 ID만 허용합니다.
- 팩트는 기존 `account-normalizer-filing/1` 입력과 같은 형식입니다. 공식 개념 QName, 시점·기간, 차원 축·멤버, 단위, 금액 또는 문자열을 명시합니다. 회사 식별자는 업무의 공통 `report.entity`로 관리합니다.
- 주석의 자유 서술과 제목은 업무용 메타데이터입니다. 자유 서술을 XBRL XML 태그로 자동 변환하거나 기존 NOTE 팩트를 덮어쓰지 않습니다. 공식 XML에 반영할 서술은 별도 NOTE 팩트로 개념·문맥·언어·값을 입력해야 합니다.
- 편집·삭제·이력 복원은 모든 팩트 승인을 해제합니다. 과거에 승인된 값과 태그를 수정 뒤에도 승인 상태로 남기지 않습니다. 택사노미 선택 기록도 팩트의 개별 승인을 대신하지 않습니다.

`공시 입력 JSON 저장`은 기존 공시 화면에서 다시 열 수 있는 초안을 저장합니다. `disclosureNotes`와 `disclosureWorkspace`에는 주석 메타데이터·업무 출처를 함께 기록하고, 팩트 승인은 모두 해제합니다. 이 JSON 저장 자체는 공식 XML 생성·기술검사·DART 접수가 아닙니다. 기존 공시 화면에서 공식 택사노미, 개념, 값, 단위, 문맥을 재검토한 뒤 승인하고 출력합니다.

## 변경 이력

각 변경은 담당자 입력값, UTC 시각, 작업, 경로, 변경 전·후 값, 이전 이력 해시, 변경 전·후 전체 상태 해시를 기록합니다. 이력 화면에서 번호별 상태를 확인하거나 과거 상태를 복원할 수 있습니다. 복원은 새 변경으로 추가되고 과거 이력을 지우지 않습니다.

파일을 열 때 최초 상태부터 모든 변경을 재실행하고 현재 상태와 대조합니다. 이력 일부나 현재 금액만 바꾼 파일은 거부합니다. 원자적 저장과 파일 바이트 해시를 사용해 저장 실패로 기존 파일이 손상되거나 다른 창에서 수정한 파일을 덮어쓰는 일을 방지합니다. 파일에 포함된 원본 경로는 업무를 여는 동안 실행·접속·조회하지 않습니다.

이 기록은 **전자서명이나 위변조 방지 공인 증빙이 아닙니다.** 담당자는 텍스트이며 인증되지 않습니다. 전체 파일과 해시를 다시 만들어 조작하거나 예전의 유효한 파일로 바꾸는 공격까지 입증·방지하지 않습니다. 원본·이력의 보관과 조직의 승인 절차를 함께 사용해야 합니다.

업무 파일은 50MB, 팩트는 50,000개, 주석은 2,000개, 변경 이력은 500개까지입니다. 값과 연결은 자동 합산하거나 유사한 제목만으로 승인하지 않습니다.

## 다음 연도 재사용

`다음 연도 업무 만들기`는 원본을 유지하고 별도 업무 ID로 새 업무를 만듭니다. 화면에서는 먼저 원업무를 `주석 업무 저장`으로 저장해야 합니다. 다음 연도 업무도 별도 이름으로 저장해 원업무와 이력을 보관하세요.

1. 회사명·식별자·식별자 체계와 연결·별도 구분을 보존합니다. 다른 회사로의 재사용은 새 업무에서 시작합니다.
2. 보고 기간을 1년 이동합니다. 새 기간은 이전 종료일 다음 날에 시작해야 합니다. 2월 29일은 다음 해 2월 28일로 조정하고 조정 내역을 표시합니다. 회계기간 자체를 변경하는 작업은 별도 새 업무에서 명시합니다.
3. 원당기 팩트와 비교기간 값을 전기 자료로 보존합니다. 비교기간은 최근 순으로 최대 3개까지 보존합니다.
4. 원당기에서 새 당기 팩트 템플릿을 만들되 **값을 공란으로 둡니다.** 전기 금액·서술을 당기 확정값으로 추정하거나 0으로 채우지 않습니다. 개념·차원·단위·기간 구조와 원본 항목 ID의 연결은 보존합니다.
5. 주석 제목·서술·구조를 복제하고 확인 필요 상태로 표시합니다. 연결 항목은 새 당기 템플릿을 우선 가리키며, 전기 자료만 있는 연결은 해당 전기 팩트를 가리킵니다.
6. 모든 팩트 승인을 해제하고 택사노미 재확인을 요구합니다. 새 버전 식별값을 넣더라도 개념명을 임의로 바꾸지 않습니다. 현재 공식 택사노미에서 태그 존재·자료형·기간·차원을 다시 검사해야 합니다.

기초 시점은 새 보고 시작일의 전날로 연결합니다. 새 기초와 보존한 전기말이 같은 개념·기간·차원·단위·언어의 팩트라면 동일한 보존 팩트를 연결하고 중복 팩트를 만들지 않습니다. 다른 기초 개념은 값이 빈 새 템플릿으로 만듭니다. 2월 28일과 29일을 이동한 뒤 서로 다른 원본 팩트의 측정조건이 겹치면 자동으로 합치지 않고 재사용을 중단합니다. 보고 기간과 비교 기간끼리 겹치는 업무도 먼저 정리해야 합니다.

원본 업무 ID, 원본 revision·상태 해시, 이전·새 보고기간, 빈 당기 항목 수, 전기 보존 항목 수, 공유 기초·전기말 팩트 수, 윤일 조정 내역을 새 업무에 기록합니다.

## 모듈과 API

`application.disclosure_workspace`는 UI나 네트워크 호출 없이 다음 서비스를 제공합니다.

```python
from application.disclosure_workspace import (
    create_workspace, add_note, update_note, upsert_fact,
    list_revisions, revision_state, restore_revision,
    reuse_next_year, save_workspace, load_workspace, export_report,
)

workspace = create_workspace(report, actor='작성자')
workspace = add_note(workspace, '회계정책', '검토할 서술', ['note_fact_1'], actor='작성자')
workspace = upsert_fact(workspace, explicitly_edited_fact, actor='검토자')
workspace = restore_revision(workspace, 2, actor='검토자')
save_workspace(workspace, '회사_2025.acdisclosure')
next_year = reuse_next_year(workspace, actor='작성자')
export_report(next_year, '회사_2026_공시입력초안.json')
```

편집 함수는 입력 업무를 변경하지 않고 새 업무 객체를 반환합니다. `save_workspace`는 저장 성공 시 `_storage`에 로컬 파일 해시를 갱신하며 이 임시 저장 정보는 파일 내용에 포함하지 않습니다. 새 업무가 기존 파일을 덮어쓰려 하면 거부하고, 같은 파일을 정상적으로 열거나 저장했던 업무만 해시 확인 후 다시 저장합니다.

## 검증

전용 테스트는 주석·팩트 편집과 삭제·복원, 승인 해제, 파일 저장 실패와 동시 수정·새 파일 경합, JSON 중복 키, 이력·현재 상태 변조, 한글 XML ID, 당기 공란·전기 보존, 반복 재사용의 비교기간 한도, 겹치는 비교 기간 차단, 윤일 조정과 측정조건 충돌, 기초·전기말 공유 팩트, 기존 공시 JSON 입력·공식 모델 호환성을 검사합니다. 합성 택사노미와 합성 회사만 사용합니다.
