# IFRS/DART 공시 준비

확정 재무제표의 개별 항목을 공시 개념에 연결하는 기능입니다. 기존 `XBRL GL XML 저장`과 별도로 업무 메뉴 또는 변환 결과의 `IFRS/DART 공시 XML`에서 엽니다. 원장 업무를 열지 않은 상태에서도 회사별 공시 입력 파일로 시작할 수 있습니다.

## 두 가지 사용 경로

| 선택한 참조 | 만드는 결과 | 수행하는 확인 |
|---|---|---|
| 이용 권한이 있는 공식 로컬 `.xsd` 진입점과 완전한 택사노미 폴더 | XBRL 2.1 인스턴스·근거 JSON·CSV·한국어 검사 보고서 | 실제 DTS를 읽는 Arelle의 자료형·기간·차원 검사와 적용 가능한 계산 관계 |
| DART 공식 엑셀 참조 | 승인한 공시 개념·금액의 CSV 대사표·근거 JSON·한국어 대사 보고서 | 엑셀에 실린 개념·자료형·기간 등의 메타데이터 확인. **XML은 생성하지 않음** |

DART 엑셀은 공식 XSD나 DTS를 대신하지 않습니다. 이 경로의 결과는 `concept-metadata-only`이며 XML·차원 허용 관계·계산 링크·DART 접수 검사를 수행했다고 표시하지 않습니다.

v0.10에서는 설치된 금융감독원 공식 작성기 9.01의 DART 2026-01-31 DTS를 읽고 불러오기 후보 XML과 기술검사 경로를 추가했습니다. 공식 작성기 설치 파일과 택사노미 원본은 제품에 포함하지 않습니다. 실행 실적은 릴리스의 `validation-summary.json`에 기록하며, 기술검사를 DART 제출 검증 실적으로 해석하지 않습니다. [공식 작성기 연동](official-writer-workflow.md)을 함께 확인하세요.

## 1. 참조와 공시 범위를 정해요

`공식 택사노미 선택`에서 `.xsd` 진입점을 선택합니다. 공식 패키지의 폴더 구조·의존 스키마·링크베이스·`META-INF`를 함께 유지합니다. 택사노미는 전용 폴더에 두고 결과는 그 밖에 저장합니다. 외부 인터넷 참조를 임의로 다운로드해 누락을 채우지 않습니다.

IFRS Foundation은 [2026 보고기간에도 IFRS Accounting Taxonomy 2025를 계속 사용하도록 안내](https://www.ifrs.org/news-and-events/news/2026/02/ifrs-accounting-taxonomy-2025-to-remain-current-for-2026/)합니다. IAS 1 기준 진입점과 IFRS 18 조기 적용 진입점은 회사의 실제 적용 기준에 맞게 선택합니다. IFRS 진입점을 선택했다는 이유만으로 국내 DART 제출 기준을 충족하는 것은 아닙니다.

DART 엑셀을 사용할 때는 `DART 공식 엑셀 참조 선택`을 누릅니다. 공시 역할별 목록과 한국어·영문 이름으로 개념을 찾고, 엑셀 참조에 근거한 대사표를 준비합니다.

`회사·공시 범위` 탭에서 회사명·기업 식별자·식별자 체계 URI·당기 시작일/종료일·연결/별도·확인자를 입력합니다. 기업 식별자 앞자리 0은 텍스트로 보관합니다. 비교금액이 있으면 `2025-01-01~2025-12-31;2024-01-01~2024-12-31`처럼 비교기간을 최대 3개 명시합니다.

연결/별도 선택은 회사가 정한 공시 범위입니다. 각 항목의 연결·별도 차원이나 회사별 추가 공시 개념을 자동으로 추정하지 않으므로 선택 진입점·개념·차원과 함께 확인합니다.

## 2. 확정 재무제표를 가져와요

- `공시 엑셀 양식 만들기`: 빈 `공시정보`·`공시항목` 시트에 실제 회사의 확정값을 입력합니다. `작성예시`·`사용법` 시트는 변환 대상이 아닙니다.
- `공시 엑셀·CSV·JSON 열기`: BS·PL·CF·CE·NOTE 항목을 읽습니다. CF는 현금흐름표, CE는 자본변동표, NOTE는 개별 주석 팩트입니다. 전체 주석의 작성·구조·완전성을 자동 생성하는 기능은 아닙니다.
- `열린 업무의 BS 가져오기`: 기존 업무의 재무상태표 표시값만 가져옵니다. 원장 순증감으로 기말잔액·손익·현금흐름을 추정하지 않습니다. 상세·소계·합계는 각각 제공된 표시값으로 유지합니다.

엑셀에는 `공시정보`의 `항목/값`과 다음 순서의 `공시항목` 열이 필요합니다.

```text
항목ID, 재무제표, 원본코드, 원본항목, 공식개념, 값, 단위, 표시배율, 정확도, 기간형식, 기준일, 시작일, 종료일, 차원JSON
```

CSV는 같은 열을 사용하며 회사·공시 범위를 앱에서 확인합니다. JSON은 `account-normalizer-filing/1` 형식으로, `value`에 이미 환산한 확정값 문자열을 넣습니다. 일반 입력을 새로 열면 모든 항목은 미승인 상태로 시작합니다.

숫자 단위는 `KRW`, `shares`, `KRW/shares`, `pure`를 사용합니다. 문자·날짜·참거짓 값의 단위는 비웁니다. 엑셀·CSV의 표시배율은 `1`, `1000`, `1000000` 중 선택하며, 값 `1,234`와 배율 `1000`은 원 단위 `1234000`으로 변환합니다. 쉼표와 괄호 음수를 지원하고 원본값·배율도 보존합니다.

`decimals`는 표시배율과 다른 정확도 속성입니다. `-3`은 천원 단위 정확도이며 값을 추가로 1,000배 하지 않습니다. 항목ID·원본코드는 텍스트로 입력합니다. 사용자 항목ID는 `originalId`로 보존하고 XML용 내부 ID는 별도로 생성합니다.

입력 파일은 50MB, 엑셀 압축해제 합계는 256MB, 공시 항목은 50,000개 이내입니다. 수식·매크로·외부 연결 대신 확정값을 준비합니다. 셀·JSON 텍스트와 전체 텍스트에도 별도 한도가 있습니다.

## 3. 개념과 항목을 승인해요

`공시 항목 연결·승인`에서 각 행을 선택합니다. 후보는 이름으로 찾은 참고 결과이며 자동 승인이 아닙니다. 공식 QName, 값, 재무제표 구분, 단위, 정확도, 기간과 차원을 직접 확인합니다.

`instant`는 기준일 하나, `duration`은 시작일·종료일입니다. 비교값의 기간은 회사·공시 범위에도 포함해야 합니다. 차원은 `{"공식접두사:축":"공식접두사:멤버"}`처럼 실제 명시적 차원의 QName으로 입력합니다. 임의 별칭이나 은행 이름을 공식 차원 코드로 바꾸지 않습니다. 형식과 실제 허용 관계는 XSD 경로에서 추가 검사합니다.

확인자 이름을 입력하고 `선택 항목 승인`을 누릅니다. 미확정 항목은 결과 출력을 차단합니다. 회사 범위·항목 내용·택사노미가 바뀌면 승인을 다시 확인합니다. 승인에는 택사노미 지문을 연결하며, 다른 지문의 공시 업무는 재승인이 필요합니다. 확인자 이름은 로그인 인증이나 전자서명이 아닙니다.

## 4. 업무와 결과를 보관해요

`공시 업무 저장`은 미확정 항목도 `.acfiling` JSON으로 보관합니다. 파일은 서명 없는 설정·검토 기록이며 원본과 택사노미를 포함하지 않습니다. 원본 입력 파일·선택한 택사노미 폴더·참조 엑셀을 별도로 보관합니다. 저장 전 원본이나 참조가 바뀌면 다시 읽고 확인합니다. 기존 `.acwork`는 원장 업무용 별도 파일입니다.

공식 XSD 경로에서 `검사 후 공시 XML 저장`을 누르면 Arelle 2.47.3이 별도 로컬 프로세스에서 실제 DTS와 XBRL 2.1 인스턴스를 읽습니다. v0.9 실행팩에는 이 검사기를 포함합니다. 검사를 통과한 결과만 새 완료 폴더로 확정합니다.

| XSD 경로 파일 | 내용 |
|---|---|
| `financial-report.xbrl` | 승인한 공시 팩트의 XBRL 2.1 XML |
| `facts.json` | 원본 코드·금액·출처·승인 등 근거 |
| `taxonomy-reference.json` | 진입점·패키지 지문·파일 해시 참조 |
| `validation-report.json` | 검사 오류·주의·수행/미수행 항목 |
| `공시검사결과.html` | 한국어 검사 보고서 |
| `DART_입력대사.csv` | 공시 개념·값·기간을 확인하는 입력·대사표 |

계산 1.0/1.1 관계는 선택한 택사노미에 존재하고 필요한 팩트가 갖춰진 경우 검사합니다. 하위 팩트가 없는 계산 연결은 통과로 간주하지 않고 계산 범위·미수행 수를 보고합니다. 일부 재무상태표 대차등식 확인도 모든 공시 필수항목·주석의 완전성이나 회계 적정성을 입증하지 않습니다. Formula·회사별 제출 규칙·공시 접수는 별도 확인 대상입니다.

DART 엑셀 경로는 `DART_입력대사.csv`, `facts.json`, `validation-report.json`, `공시대사결과.html`을 저장합니다. 보고서의 `xmlGenerated=false`와 미수행 항목을 확인합니다. 엑셀에 차원 이름이 있는지 확인하는 것과 실제 축·멤버 허용 관계 검사는 구분합니다.

## DART에서 마무리할 작업

[금융감독원 DART 접수시스템의 최신 자료·공식 작성기 안내](https://filer.fss.or.kr/raaf001/search.do)를 확인하고 공식 XBRL 작성기에서 제출용 최종 파일을 생성·검사한 뒤 DART 편집기에 삽입·제출합니다. 앱의 XML이나 CSV가 작성기에 자동 불러오기되거나 공시가 수리된다고 보장하지 않습니다.

IFRS/DART 원본 택사노미·공식 엑셀은 실행팩과 공개 예제에 재배포하지 않습니다. 이용 권한이 있는 공식 로컬 파일을 선택합니다. 이 앱이 생성한 파일은 해당 파일·택사노미 지문에 연결된 기술 확인 결과이며 공식 원본의 진위 인증이나 공시 접수 결과가 아닙니다.

## CLI

```text
python convert.py --filing-template "공시입력양식.xlsx"
python convert.py "검토한공시업무.acfiling" --filing --taxonomy "공식패키지/선택진입점.xsd" --out "새결과폴더"
python convert.py "검토한공시업무.acfiling" --dart-reference "DART공식참조.xlsx" --out "새대사폴더"
```

`--approve-filing "확인자"`는 입력된 개념·값·기간·차원을 사용자가 확인했다는 명시적 승인 옵션입니다. 후보 자동 승인이나 필수 공시항목 자동 완성 기능으로 사용하지 않습니다. 실행 기록과 버전별 자동 검사 범위는 릴리스의 `validation-summary.json`에서 확인합니다.
