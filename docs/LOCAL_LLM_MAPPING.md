# 로컬 LLM 계정 후보와 사람의 승인

v0.13은 이 컴퓨터에서 실행 중인 Ollama의 로컬 모델에 계정 후보를 요청합니다. 사전·별칭 후보는 계속 사용할 수 있고, 로컬 LLM은 추가 추천 경로입니다. 추천은 연결 확정이 아닙니다. 모델이 추천한 3개 중 하나를 고르거나 전체 표준 계정 목록에서 다른 계정을 직접 선택한 뒤 사람이 확인자로 승인합니다.

## 준비

1. [Ollama 공식 Windows 안내](https://docs.ollama.com/windows)에 따라 Ollama와 로컬 텍스트 생성 모델을 준비합니다. 앱은 서버·모델을 자동 설치하거나 내려받지 않습니다.
2. 예를 들어 로컬 GGUF 모델 `qwen3:4b`를 설치한 뒤 Ollama를 실행합니다. 이 PC의 실제 시험에는 해당 모델을 사용했습니다. 모델 파일의 용량과 추론 속도는 선택한 모델과 PC 메모리·CPU·GPU에 따라 달라집니다. 모델과 Ollama는 이 앱 실행팩에 포함되지 않습니다.
3. 로컬 전용 운영에는 공식 안내의 `OLLAMA_NO_CLOUD=1` 환경설정을 사용합니다. 이 앱은 설치 목록의 Cloud/원격 모델을 제외하고 추천 직전 모델 상세정보를 다시 확인합니다. 사용자가 설치한 서버의 동작 자체를 암호학적으로 인증하는 기능은 아닙니다.
4. 앱의 `로컬 LLM 설정`에서 로컬 주소와 설치 모델을 확인하고 선택합니다. 기본 주소는 `http://127.0.0.1:11434`입니다. 모델이 없거나 연결되지 않으면 기존 사전 후보와 직접 선택으로 계속 검토할 수 있습니다.

설정은 로컬 사용자 데이터 폴더의 `local_llm_settings.json`에 보관합니다. EXE에서 `%LOCALAPPDATA%/AccountDataNormalizer`를 사용하며 API 키가 필요하지 않습니다. 설정에는 로컬 주소·모델명·대기 시간만 저장하고 Git이나 릴리즈에 포함하지 않습니다.

## 추천과 승인

- 원본 계정을 선택해 추천을 요청합니다. 같은 회사·시스템의 동일 계정은 원장 행마다 모델을 호출하지 않고 고유 계정 단위로 처리합니다.
- 추천 결과는 사전에 있는 서로 다른 표준 계정 후보 3개와 한국어 근거입니다. 코드·형식의 유효성과 회계적 적합성은 별개이며, 관련성이 낮거나 틀린 후보도 포함될 수 있어 사람이 확인합니다. 점수나 확률로 회계적 정확성을 표현하지 않습니다.
- 코드는 현재 사전에 있어야 하고 원장에서는 상세 계정이어야 합니다. 재무제표 구분과 사람이 거절한 후보를 반영합니다. 3개가 채워지지 않거나 중복·잘못된 코드가 오면 임의 후보로 채우지 않고 재추천을 안내합니다.
- 추천 후보를 고르는 행위와 승인 버튼은 분리합니다. 사람이 다른 계정을 직접 선택할 수 있으며 모델 추천만으로 연결 상태·표준화 금액·승인 이력을 변경하지 않습니다.
- 계정명·회사·시스템·사전·거절 상태·로컬 LLM 설정이 바뀌면 이전 추천을 그대로 적용하지 않습니다. 모델명과 모델 지문은 추천 근거에 기록됩니다.

## 모델에 보내는 범위

단일 원본 계정의 **계정코드·계정명·입력종류·BS/PL 구분**과 적합한 표준 계정 사전의 **코드·이름·구분·별칭 최대 8개·명시된 정의**만 프롬프트에 넣습니다. 전체 원장, 금액, 전표, 거래처, 파일 내용, 회사 이름은 프롬프트에 넣지 않습니다. 계정명 자체에 포함한 텍스트는 계정명으로 전달됩니다.

연결 주소는 HTTP loopback IP 또는 localhost만 허용하고 localhost는 `127.0.0.1`로 고정합니다. 프록시 환경변수를 사용하지 않고 다른 주소로의 HTTP 리다이렉트를 따르지 않습니다. 외부 API·모델 자동 다운로드·웹 검색·도구 실행 기능은 없습니다. localhost 서버의 Cloud 중계 모델도 선택 대상에서 제외하고 응답의 원격 모델 표시가 있으면 적용하지 않습니다.

## 범위와 오류

현재 지원은 Ollama의 로컬 GGUF 텍스트 생성 모델입니다. 적합한 표준 계정은 3~300개이며 JSON 요청은 192KB, 응답은 4MB, 추천 대기 시간은 5~300초로 제한합니다. 무한 스트림 대신 완료된 JSON 응답 하나만 읽습니다. Qwen3에는 `think:false`, `num_ctx:8192`, `num_predict:1000`, `temperature:0`을 지정합니다. 명령·거래 지시문을 계정명에 넣어도 이를 데이터로 취급하도록 요청하며 응답은 코드·개수·중복·길이·자료형을 재검사합니다.

연결 실패, 모델 미설치, Cloud 모델, 시간 초과, 미완료·절단 응답, JSON 형식 오류는 추천 실패입니다. 실패해도 현재 연결과 사람의 검토 상태는 유지합니다. 로컬 모델 추천은 회계 판단, 감사 결론, 공식 IFRS/DART 개념의 승인이나 공시 적정성을 보장하지 않습니다. 자체 표준 계정의 추천과 공식 공시 팩트의 개념 검토는 별도 과정입니다.

로컬 TCP 연결이 일시적으로 reset되거나 Ollama 내부 loopback 서버의 tokenize/completion 연결이 reset·EOF로 끊겨 HTTP 500을 반환한 경우만 원래 대기 시간 안에서 한 번 재요청합니다. 두 경우는 재시도 예산을 공유합니다. 일반 HTTP 오류, 모델 미설치·잘못된 모델, 메모리 부족과 시간 초과는 자동 재시도하지 않습니다. 오류 JSON은 최대 8KB만 읽고 본문·파일 경로를 출력하지 않으며, 분류된 사유와 내부 단계만 진단 정보로 보관합니다. 다른 서버·모델로 자동 전환하지 않고 재요청도 승인이나 결과 저장을 실행하지 않습니다.

## 구현과 공식 참고자료

- `application/local_llm/config.py`: 로컬 주소·모델명·설정 저장
- `application/local_llm/transport.py`: 직접 loopback HTTP와 응답 한도·시간 제한
- `application/local_llm/prompts.py`: 최소 계정 입력과 후보 3개 구조·검사
- `application/local_llm/client.py`: 설치 모델·로컬 가중치 확인과 추천 호출
- [Ollama Chat API](https://docs.ollama.com/api/chat): `/api/chat`, `stream:false`, `format`, `think`, 추론 옵션
- [Ollama 설치 모델 목록 API](https://docs.ollama.com/api/tags): `/api/tags`의 설치 모델 정보
- [Ollama Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs): JSON schema와 낮은 temperature
- [Ollama FAQ](https://docs.ollama.com/faq): 로컬 전용 운영과 `OLLAMA_NO_CLOUD=1`
- [Ollama 공개 API 자료형](https://github.com/ollama/ollama/blob/main/api/types.go): `remote_host`·`remote_model`로 원격 모델 구분

실제 모델 시험과 서비스·EXE 검증 범위는 릴리즈의 `validation-summary.json`에 기록합니다. 테스트 서버를 사용한 구조·오류 검증과 실제 로컬 모델 추론 실적을 구분합니다.
