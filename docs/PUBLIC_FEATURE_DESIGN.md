# 공개 기능을 참고한 자체 공시 검토 설계

확인일: 2026-10-29. 공개된 제품 기능 설명을 업무 요구사항 수준에서 참고하고, 기존 자체 코드와 공개 공식 규격에 따라 독립적으로 구현했습니다. 인벡터 계정·내부 API·소스·설치 파일·비공개 산출물을 사용하지 않았습니다.

## 참고한 공개 자료

- [인벡터 DSD 기능](https://invector.co/dsd): 정산표·문서 변환과 문서 변경 비교라는 공개 기능 범주.
- [인벡터 XBRL 기능](https://invector.co/xbrl): DSD·IXD 숫자 대사와 태깅 검토라는 공개 기능 범주.
- [OpenDART 공시서류 원본파일 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003): 접수번호로 제공하는 공시 원문 ZIP/XML. API 결과를 로컬에서 준비한 뒤 읽으며 앱이 인증키를 요구하거나 공시를 전송하지 않습니다.
- [DART 접수시스템 자료실](https://filer.fss.or.kr/raaf001/search.do): 작성기·공시 문서의 공식 안내. 로컬 IXD 구조 검사는 기존 읽기 전용 검사기를 재사용합니다.
- [XBRL International XBRL 2.1](https://specifications.xbrl.org/work-product-index-group-base-spec-base-spec.html): 팩트의 개념·회사·기간·단위·문맥 비교 기준. 접두사와 XML 내부 ID 대신 확장 QName과 실제 문맥을 비교합니다.

## 자체 구현의 판단 기준

DSD는 공시 문서의 표·셀이고 IXD의 XBRL은 개념·문맥을 가진 팩트입니다. 문서 안의 비슷한 이름이나 같은 숫자만으로 동일 항목임을 확정하지 않습니다. 선택한 셀과 팩트, 회사·기간·단위·차원 및 표시 배율을 사용자 대응표에 보관하고 원본 해시와 함께 확인합니다. 대응이 없는 항목은 미대응이며 0으로 대체하지 않습니다.

주석 업무는 공시 입력과 별개로 제목·서술·연결 팩트를 보관합니다. XBRL 팩트로 내보내려면 명시적인 개념과 문맥을 지정하고 기존 공식 DTS 검토 경로를 거칩니다. 값·개념·회사·기간·택사노미 변경은 기존 승인의 근거를 바꾸므로 재확인이 필요합니다.

변경 이력은 이전 상태로 돌아가더라도 기존 기록을 지우지 않고 복원 이벤트를 추가합니다. 기록은 로컬 사용자 입력이며 신원을 인증하지 않습니다. 다음 연도 업무는 기간·비교 수치·새 당기 공란을 구분하고 회사별 확정값을 추정하지 않습니다.

소프트웨어의 표·셀 숫자 대사와 이력 검사는 회계적 적정성, 회사별 주석 완전성, 공식 생성 provenance 또는 DART 접수 여부를 판정하지 않습니다. 시험 입력은 자체 합성자료이며 공식 택사노미·작성기·고객 공시자료를 실행팩에 복사하지 않습니다.
