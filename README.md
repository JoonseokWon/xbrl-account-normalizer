# 회계데이터 표준화

XLSX·CSV·TSV 원장과 재무상태표를 공통 계정코드로 연결하는 Windows 앱입니다. 회사·ERP별 입력 설정, 계정 사전 관리, 전표별 분개와 대사, 업무 저장·다시 열기를 지원합니다.

**v0.12.0-preview.1 — DSD·IXD 숫자 대사, 주석·공시항목 편집, 변경 이력·복원, 다음 연도 업무 재사용을 추가했습니다. 상단 `공시 검토` 메뉴에서 시작하세요. [대사 사용법](docs/DISCLOSURE_COMPARE.md)과 [주석 업무 사용법](docs/DISCLOSURE_WORKSPACE.md)을 참고하세요.**

공식 XSD 경로는 실제 스키마를 읽어 XML을 만들고, DART 엑셀 참조 경로는 XML을 생성하지 않는 입력·대사표입니다. 설치된 작성기 9.01의 일반 화면에는 외부 데이터 가져오기 메뉴가 없습니다. 별도 로컬 연동 시험에서는 합성자료로 공식 작성기 본체의 제출용 IXD 생성과 기술검사 오류·경고 0건을 확인했습니다. 이 시험용 생성 연결은 이번 EXE의 범용 생성 기능에 포함되지 않습니다. 앱은 사용자가 준비한 IXD를 읽어 대사하며 기술검사·입력 대사·공식 생성·DART 접수 상태를 구분합니다. IFRS/DART 택사노미와 공식 작성기는 재배포하지 않으며 이용 권한이 있는 로컬 설치를 사용합니다.

## 공시 검토와 반복 업무

- **DSD·IXD 대사:** 로컬 DSD/XML/ZIP과 제출 후보 IXD를 선택하고 표의 숫자 셀과 팩트를 명시적으로 연결합니다. 회사·기간·단위·차원과 표시 배율을 확인한 뒤 값 차이·미대응·모호한 대응을 구분하고 결과를 저장합니다. 이름 유사도만으로 연결을 승인하지 않습니다.
- **주석 편집:** 새 회사·기간의 공시 업무를 시작하거나 기존 공시 JSON을 가져와 주석 제목·서술·연결 항목과 명시적인 공시 팩트를 편집합니다. 자유 서술은 공식 XBRL 태그가 자동 부여된 공시문으로 간주하지 않습니다.
- **변경 이력:** 변경 전후 값과 확인자·시간을 보관하고 이전 상태를 새 변경으로 복원합니다. 해시 연결로 내부 불일치를 찾지만, 전자서명·사용자 인증·악의적인 전체 재작성 탐지를 대신하지 않습니다.
- **다음 연도 재사용:** 회사와 주석 구조·개념 연결을 유지하며 이전 당기는 비교기간으로 보관합니다. 새 당기 값은 공란으로 만들고, 승인과 택사노미를 다시 확인합니다. 과거 금액을 새 당기의 확정 금액으로 복사하지 않습니다.

공시 업무의 초안 JSON은 기존 `IFRS/DART 공시 XML` 화면에서 열어 공식 택사노미를 선택하고 검토·승인할 수 있습니다. DSD·IXD 대사 일치는 필수 주석 완전성이나 DART 접수 성공을 의미하지 않습니다. [공개 자료와 자체 설계 근거](docs/PUBLIC_FEATURE_DESIGN.md)를 참고하세요.

## Windows에서 시작하기

1. [GitHub 릴리스](https://github.com/JoonseokWon/xbrl-account-normalizer/releases)의 Windows 실행팩 ZIP을 내려받아 압축을 모두 풀어요.
2. `AccountDataNormalizer.exe`를 실행해요. Python이나 Codex 설치는 필요하지 않아요.
3. EXE와 `_internal` 폴더를 함께 보관해요. 앱은 로컬 파일을 처리하며 런타임에 서버로 원장을 전송하지 않아요.

### 작업 순서

새 기능의 자세한 사용법은 [회사별 반복 업무](docs/COMPANY_WORKFLOW.md)를 참고하세요.

- **자료 준비:** `새 파일 열기`로 같은 회사·양식의 XLSX·CSV·TSV 파일을 선택해요. 여러 월의 파일도 함께 선택하고 회사·기간·금액 단위를 확인해요.
- **열 연결:** 사용할 시트·제목 행과 원본 열을 연결해요. 은행·계좌번호·거래처·부서·프로젝트·증빙번호는 선택 항목이에요. 입력 설정 저장/불러오기로 같은 회사·ERP의 열 설정을 재사용해요.
- **계정 검토:** 원본 코드, 후보, 추천 근거를 보고 표준 계정을 연결하거나 후보를 제외해요. 계정명·코드로 검색하고 미확정 계정만 볼 수 있어요.
- **변환 결과:** 전표별 분개에서 여러 차변·대변 행을 함께 보고 변환·시산표 대사에서 차이를 확인해요. 원장·분개·대사·오류 행을 두 번 누르면 원본 열과 값을 볼 수 있어요.

상단 업무 메뉴에서 원본과 검토 상태를 `.acwork`로 저장하고 다시 열 수 있습니다. 새 보조자료 연결로 가져온 시산표·통제 원본과 열 설정도 함께 보관합니다. 원본이 불러온 뒤 변경됐으면 저장을 중단합니다. 다시 열면 포함된 원본·사전·검토 상태로 재계산하고 외부 승인 이력은 적용하지 않습니다.

업무 → 표준 계정 사전 관리에서 상세계정·그룹·상위코드·리드·별칭을 관리합니다. 사전 내용이 바뀌면 새 버전으로 보관하고 현재 연결은 재확인합니다. 같은 표준 계정으로 연결해도 원본 은행 계정과 선택한 세부정보는 보존합니다.

검토본은 미확정 계정이 있어도 저장할 수 있습니다. 실제 감사 연결 데이터는 오류·미확정 상태를 먼저 해결해야 합니다. 새 연결은 이름 유사도나 코드 일치만으로 자동 승인하지 않습니다.

어느 단계에서든 상단의 `새 파일 열기`로 다른 파일의 작업을 시작할 수 있습니다. 새 파일의 시트·열 정보를 읽은 뒤 이전 회사 정보·열 연결·검토 결과를 초기화합니다. 파일 선택 취소나 읽기 실패 시 현재 작업은 유지합니다. 저장하지 않은 계정 연결이 있으면 파일을 바꾸기 전에 확인합니다.

## UI/UX와 모듈

[토스 UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide)를 참고해 해요체, 명확한 행동 이름, 예상 가능한 이동, 정보 중심의 화면을 적용했습니다. 자료·작업 정보·연결 예시·요약을 서로 다른 크기의 카드에 배치한 벤토 그리드입니다. Windows에서는 왼쪽 내비게이션과 고정 상단 작업 버튼을 사용하고 본문은 창 크기에 따라 스크롤합니다. 토스 로고와 그래픽은 사용하지 않습니다.

계산·매핑, 엑셀 입출력, 작업 서비스, 화면, 공통 컴포넌트, 테마, 백그라운드 작업을 나눴습니다. [모듈 구조](docs/ARCHITECTURE.md)와 [UI 설계 반영 내용](docs/UI_DESIGN.md)을 확인할 수 있습니다. CLI도 같은 서비스를 사용합니다.

Windows에서는 설치된 맑은 고딕을 우선 사용하고, 해당 글꼴이 없으면 포함된 Noto Sans KR을 사용합니다. 본문 11pt·안내 10.5pt로 키우고 보조 글자와 입력 안내의 대비를 높였습니다. Windows 글꼴은 실행팩에 복사하지 않습니다.

## 연결 규칙

`00101 보통예금`, `00102 당좌예금` → `A1102 현금성 예금` → `CASH / 현금분석`처럼 다대일 계정 연결을 지원합니다. 현재 사전은 67개 항목(상세계정 64개·그룹 3개)의 실험용 자체 코드이며 공식 DART·IFRS XBRL 택사노미가 아닙니다.

- 한글·영문 별칭, 공백·구두점 정규화, 문자열 유사도로 상위 후보 3개와 근거를 제안합니다. 점수는 정확도·확률이 아닙니다.
- 현재 매핑은 로컬 LLM을 사용하지 않습니다. 계정 사전·별칭·문자열 유사도와 회사별 승인·거절 이력으로 후보를 제안하며, 공시 개념도 이름 후보를 검토 후 승인합니다. 외부 LLM API나 모델 서버 호출은 없습니다.
- 본점·관리부 같은 고정된 조직 표기는 별칭 비교에서 분리합니다. 장기·단기·상각누계·질권설정 같은 회계 의미는 제거하지 않습니다. 수수료·예치금·선급·정산계정은 정의 확인을 안내합니다.
- 승인 이력은 입력종류·회사·원천시스템·원본코드·계정명·사전 버전이 모두 같을 때 재사용합니다.
- 거절한 후보는 같은 범위에서 다시 추천하지 않습니다. 현재 사용자가 지정한 미확정 상태는 이력보다 우선합니다.
- 확인·거절 이력은 결과를 저장할 때 보관합니다. 확인자 이름은 텍스트 기록이며 로그인 인증은 아닙니다.

EXE의 로컬 이력과 오류 기록은 `%LOCALAPPDATA%/AccountDataNormalizer`에 저장합니다. 사용자 원본·이력·로그는 Git과 릴리스에 포함하지 않습니다.

## 입력과 결과의 범위

입력은 확정값 XLSX·CSV·TSV, 파일당 50MB·100,000행·80열 이하입니다. 같은 양식의 최대 24개 파일, 합계 250MB·250,000행을 한 업무로 처리합니다. XLSX와 CSV를 한 번에 섞지 않습니다. CSV는 UTF-8/CP949 인코딩을 지원합니다. 원장 필수 정보는 회사·전기일·전표번호·행ID·계정코드·계정명·차변·대변입니다. CSV 코드는 텍스트로 읽으며 앞자리 0이 필요한 XLSX 코드는 텍스트 셀이어야 합니다. 수식·매크로·외부 연결·내장 개체는 확정값 사본으로 준비합니다.

파일을 묶어도 전표번호를 임의로 바꾸거나 중복을 삭제하지 않습니다. 10,000행 초과 검토 엑셀은 순차 저장하며 Excel 매핑표 드롭다운을 생략합니다. **통합감사 v2.3은 총계정원장 1,048,575행까지 읽고 보조표는 시트당 10,000행**으로, 표준화 앱의 업무당 250,000행을 한 파일로 그대로 넘길 수 있습니다. 큰 원장은 새 감사 EXE v2.3 이상을 사용합니다.

통화는 KRW이며 원/천원/백만원을 원으로 환산합니다. 개별 금액 절댓값 10조원 이하의 정수를 지원합니다. 양쪽 금액 공란, 음수 차대, 중복 전표행, 전표 차대 불일치는 이슈로 표시합니다. 한쪽 공란만 기본 프로필 규칙에 따라 0으로 처리합니다.

재무제표는 **BS 재무상태표**를 지원합니다. PL에는 기간 시작·종료 규격이 추가로 필요합니다. 상세·소계·합계를 구분하고 중복 합산하지 않습니다. 원장 당기순변동을 기말잔액으로 대체하지 않습니다.

검토 결과에는 검토 엑셀·표준 JSON·부분 연결 JSON·입력 프로필이 있습니다. 검토 엑셀에는 전표별 분개·세부정보·대사도 들어갑니다. **시산표·통제자료 열 연결**에서 회사 양식의 파일을 연결하거나 기존 보조 양식을 사용해 **통합감사 입력 저장**으로 7시트 입력을 만듭니다. 출처 JSON에 각 전표 행의 원본 위치와 세부정보를 남깁니다. 통제 금액과 행 수는 원본 열에서만 읽으며 원장으로 채우지 않습니다. [보조자료 연결 사용법](docs/AUDIT_EXPORT.md)을 참고하세요.

**XBRL GL XML 저장**은 계정 검토를 마친 원장·BS를 공식 COR+BUS 태그로 저장하고, 공식 XSD와 원본 행·금액·코드·차대·통화를 다시 확인합니다. 원장은 journal, BS는 balance 자료로 구분합니다. 스키마 패키지·행 출처·검사 보고서를 함께 저장하며 인터넷 없이 실행됩니다. 자체 공통 코드의 IFRS/DART 개념 매핑과 DART 공시 제출은 포함하지 않습니다. [XML 출력의 의미와 검사 범위](docs/XBRL_GL.md)를 확인하세요.

## 소스로 실행·빌드하기

Python 3.11 이상에서 `설치.cmd`를 실행한 다음 `변환실행.cmd`로 GUI를 엽니다. 또는:

```text
python -m pip install -r requirements.txt
python main.py
python convert.py "원본.xlsx" --company "COMPANY-A" --system "ERP-A"
python convert.py "원본.xlsx" --inspect
python convert.py "원본.xlsx" --column-map config/column_mapping.example.json
python convert.py "확인한업무.acwork" --xbrl --out "결과폴더"
python convert.py --check-xbrl "XBRL_결과폴더" --out "검사보고서폴더"
python convert.py --filing-template "공시입력양식.xlsx"
python convert.py "확정공시.json" --filing --taxonomy "공식택사노미/진입점.xsd" --approve-filing "확인자" --out "결과폴더"
python convert.py "확정공시.json" --dart-reference "DART공식택사노미.xlsx" --approve-filing "확인자" --out "대사표폴더"
```

시트명·기본 별칭은 `config/profile.json`, 계정 사전은 `config/catalog.json`에서 설정합니다. CLI의 `--no-history`는 이력 읽기·저장을 모두 끄며 `--history`로 다른 이력을 지정할 수 있습니다.

Windows 실행팩 빌드:

```text
python -m pip install -r requirements-build.txt
python tools/build_windows.py
python tools/package_release.py
```

[새 회사 변환 예제](samples/새회사변환예제/)와 [여러 회사 원장](samples/여러회사매핑/)을 제공합니다. GL의 250,000행 처리와 공시 팩트의 재무제표·비교기간·단위·차원·승인·합계 오류 차단을 별도로 검사합니다. 소스·EXE·GUI·단위 검사의 버전별 결과와 제외 사유는 릴리스의 `validation-summary.json`에 담습니다. 설치된 공식 작성기 9.01의 DART 2026-01-31 DTS를 읽는 경로를 확인했습니다. 기술검사 실적과 공식 작성기의 가져오기·최종 생성 실적은 별도로 기록하며 DART 접수는 수행하지 않습니다. GUI 시험에서 OS 파일선택창은 경로로 대체합니다. 실사용 자료·감사결론을 확인한 결과는 아닙니다. [수동 확인 목록](docs/MANUAL_VALIDATION.md)을 함께 제공합니다.
